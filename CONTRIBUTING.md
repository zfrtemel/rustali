# Contributing to Rustali

Thanks for your interest. This document explains how we work so your contribution
lands smoothly. Türkçe sürüm: [CONTRIBUTING.tr.md](docs/tr/contributing.md) (yakında).

## Ground rules

- Be kind. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
- Discuss before building: open an issue (bug) or a discussion/RFC (feature) first.
  Small fixes (typos, docs, obvious bugs) can go straight to a PR.
- Every behaviour change ships with tests and docs in the same PR.

## Development setup

```bash
rustup default stable                 # MSRV is stable-2; see Cargo.toml rust-version
cargo install cargo-binstall
cargo binstall cargo-nextest cargo-insta cargo-deny cargo-expand cargo-watch
cargo build --workspace
cargo nextest run --workspace --all-features
```

Windows: install *Visual Studio Build Tools* with the "Desktop development with C++"
workload (provides `link.exe`). PostgreSQL tests need `TEST_DATABASE_URL`; without
it they are skipped and only the SQLite suite runs.

## Repository layout

Single Cargo workspace; see `Cargo.toml` and the `crates/` directory. Dependency
direction is strictly `core ← router ← orm ← migrate` and `core ← {view, auth, ...}`.
Never add a dependency from `core` to a higher-level crate.

## Coding standard (enforced by CI)

- `cargo fmt --all` (rustfmt.toml) and `cargo clippy --all-targets --all-features -D warnings`.
- Every crate starts with `#![forbid(unsafe_code)]` and `#![deny(missing_docs)]`.
- Library crates use `thiserror`; `anyhow` only in binaries and examples.
- Public items have `///` docs with at least one runnable `# Example`.
- Proc-macros get `trybuild` tests for both happy paths and error messages.
- Snapshot tests use `insta`; review changes with `cargo insta review`, never
  blindly accept.

## Commits and pull requests

- Conventional Commits: `feat(orm): add soft deletes`, `fix(router): ...`,
  `docs:`, `refactor:`, `test:`, `chore:`. Scope = crate name without prefix.
- One logical change per PR. Rebase on `main`; no merge commits.
- Fill in the PR template. Link the issue. CI must be green.
- Architectural decisions are recorded as ADRs under `docs/adr/`. If your PR
  changes an architectural decision, add or supersede an ADR.

## Release process

Maintainers only. Versions are lockstep across all crates (`workspace.package.version`),
tagged with `cargo-release`, changelog generated by `git-cliff`.
